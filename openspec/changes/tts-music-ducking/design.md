## Context

顶层 `music_duck` 是贯穿整段放歌的音量层，不能拿它的原值恢复 TTS 的临时降音量。例如放歌前 70、放歌时 20，TTS 应只做 20→10→20，音乐结束才恢复到 70。

## Goals / Non-Goals

- 目标：思考/合成不降，首句即将开播时降，整轮播报保持，结束恢复；无音乐无操作，静音/极低音量不调大。
- 目标：重叠轮次、取消、失败与重连有确定行为，手动控制优先。
- 非目标：不调整 TTS 增益，不改音乐播放/进度/原生指令过滤，不扩展 mp3/miplayer 兼容路径，不承诺比例等于听感响度比例。

## Decisions

1. 使用独立的 `tts.music_duck`，默认关闭；管理台登记，保存热生效。仅 WAV/notify 实际播放路径申请临时音量。
2. 回答上下文携带会话，前缀、流水线及错误提示共用。登记不改音量，首句启动才保存；整轮关闭且实际播放引用全部返回才恢复。旧轮次关闭不影响新轮次持有者。
3. 所有音乐音量读改写由同一 mutex 串行化；不持有播放状态锁等待设备 RPC。手动选择成功后释放临时控制权，本轮后续句子不再自动降低。
4. 手动相对调节基于实际临时音量；静音后取消静音回到正常音乐音量。外部按键只在读到数值变化时可检测，改回同值无法识别。
5. 原子写 `tts-music-duck.json` 成功后才降低。恢复前核对实际值，只恢复仍等于应用值的音量。失败保留记录；重连/下一次播报重试，先恢复临时层再恢复音乐会话层。
6. 取消上下文无法证明设备 aplay 已退出；保持引用直到播放 RPC 返回。不在本变更中重做停止播放器机制。

## Risks / Trade-offs

- 降音量增加开播前的读写 RPC，随后还有下载准备，首声延迟与压低幅度需真机验收。
- 程序退出或连接中断时，音量可能暂时保留在低值，待重连核对恢复。
- 物理按键与服务端命令不是硬件原子事务，核对后再次手动更改仍有很短的竞态窗口。
- 仓库默认关闭；2026-11-03 用户要求部署后运行配置开启 50%，仅更新服务端、未触发测试音；未进行听感确认前不宣称真机验收通过。

## Migration Plan

部署服务端后可在管理台启用，验证 20→10→20；再测多句、打断、静音及重连。回滚先关闭开关，使持有的临时音量恢复后再退旧服务端，不整份覆盖跨平台配置。
