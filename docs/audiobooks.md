# 听书：复用知识库，独立管理播放与音频

## 使用方式

书籍只在知识库导入和发布一次；管理台新增 `#audiobooks`（听书）。听书管理章节、音频缓存、预生成和书签，知识库继续负责正文与版本。只有启用、已发布且 `kind=book` 的资料进入书架。

语音示例：

- 「小爱同学，我想听书，我们有哪些书？」
- 「我想听《把时间当作朋友》，从第一章开始。」
- 「有哪些章节可以选？」
- 「小爱同学，暂停听书 / 继续听 / 下一章。」
- 「小爱同学，接着听《把时间当作朋友》。」

模型只调用 `list_books`、`list_book_chapters`、`play_book`、`control_book`、`get_book_playback`。目录工具返回章节元信息，不包含正文；播放工具没有 text 参数。服务直接读取已发布正文，校验 SHA256/Git blob，清理 Markdown 标记后送入现有豆包网页版 TTS。模型不需要逐字生成、复述或概括整章，也不需要每段再调用一次工具。

“第一章”按真实标题对应的 chapter_id 选取；前言、第〇章不被误当成第一章。无 chapter_id 时从已有书签续听，没有书签则从书的开篇开始。已经播完整本时可重新从头听。

## 合成节奏和缓存

默认每段最多 180 字，优先在段落和句末切开。单个听书服务最多一个在途合成请求，新的网络请求之间至少间隔 1000ms；只准备当前段及后面 2 段，允许配置 1–3 段预取。暂停后不发起新合成，已经在途的一段允许完成并落盘。连续失败三次停止生成并显示错误，不跳过失败段。

首段准备好、对话确认语播完、原生接管收尾后即可起播；不会等待整章合成。往后播放时按消费速度向前准备，缓存命中直接复用。换书或切章取消旧请求，旧结果即使迟到也不能写入新播放会话。

音频保存在 config 同级的 `audiobooks/audio/`，通过 `/audiobooks/audio/{内容散列}.wav` 提供给音箱，支持 HTTP Range。缓存键包含实际朗读文本、音色、情绪、格式、采样率、码率、语速和音调。相同配置和文本复用原文件；修改声音或正文后生成对应的新缓存，旧文件保留。目录可以通过 `audiobook.cache_dir` 指定。听书缓存不进入普通对话 TTS 的清理范围，也不会在播完后删除。当前没有自动配额淘汰；应将目录作为用户数据单独备份。

听书专用合成要求收到 `TTSEnded` 才保存成功结果；断线后的半段不能成为永久缓存。还会验证 WAV 数据长度和时长，异常缓存被移除后按限次策略重试。

## 播放、插话和书签

听书音频使用现有 `mediaplayer` 背景媒体路径，替换当前音乐；不是把正文加入聊天回答的 notify TTS 队列。这样可以复用设备暂停/继续、原生指令隔离、后台播放状态追踪。音量使用媒体音量；聊天确认语和回答继续使用独立 notify TTS 音量。

接受新的有效对话时暂停书籍；整轮回答与原生接管结束后继续。用户明确暂停、停止或换成音乐后，不允许旧对话的收尾恢复听书。音乐选歌、听书续段和停止共用媒体操作锁；书籍自然结束不能掉回上次网易云歌单。播放中没有唤醒词的本地识别默认丢弃，避免正文里的命令词驱动音箱；原生“小爱同学” final 仍走正常接管。

`progress.json` 原子保存每本书的版本、章节、当前段、分段规则版本和正文散列。只在播放器确认自然结束后推进，生成成功不代表已经听过。服务重启时不主动开始新播放，保留当前段供用户续听；可能重听当前短段。它不是逐秒断点。发布版本、正文或切段规则发生变化时要求重新选章，避免错误套用旧偏移。

`playback.json` 记录当前音箱媒体属于听书。重启后的设备连接会停止遗留段落，避免把书的播完事件当成旧歌单的“下一首”。音箱本身在服务断开到重连期间可能仍把当前段播完。

只清理展示标记，不改写叙述。图片、代码块、表格不送去读；保留普通段落、标题、引用和链接可见文字。技术书中的这些视觉内容需要回到知识库阅读，听书不保证覆盖它们。

## 配置

```yaml
audiobook:
  enabled: true
  cache_dir: ""           # 默认 config 同级 audiobooks/
  chunk_chars: 180         # 80–400
  prefetch: 2              # 后续预取 1–3 段
  synthesis_gap_ms: 1000   # 至少 500ms
```

沿用 `tts` 的豆包音色、语速、音调、情绪，听书输出固定 WAV。独立后台任务不依赖一轮 Codex 对话持续存活。配置变动会提示重启；书籍导入/发布后刷新书架即可。

## 验证和当前边界

自动化测试覆盖真实书库目录、元信息不泄漏正文到模型、原文分段、预生成上限、单飞合成、缓存重放、取消旧合成、对话让位、明确暂停、书签重启续听、切歌所有权、清单校验、WAV 截断拒绝与 Range 拉取。

`XIAOAI_AUDIOBOOK_TTS_LIVE=1 go test -run '^TestAudiobookTTSLive$' -v` 可显式连接豆包测试合成和无网络缓存复用，不连接音箱。普通 go test 不访问 TTS 网络。

长书连续播放仍需音箱验收：WAV 是否被当前固件正确解码、自然结束状态是否可靠、分段边界的停顿以及插话后的原位置继续。当前沿用媒体状态轮询推进，不承诺无缝拼接；设备若只报空闲且没有可靠的曲尾位置，会保留进度等待处理，不凭墙钟猜测播完。生产部署与人耳验收应单独记录，不能用本地测试代替。
