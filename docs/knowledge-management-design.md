# 知识库管理设计草案

状态：第一期已实现，尚待部署验收。日期：2026-11-03。

实现结果：管理台 `/ui/#knowledge` 已提供资料、检索试验、使用规则三个入口；Go 管理 API 已接入导入、校验、发布、回滚、启停与并发 generation 检查；Node worker 已改为读取多资料 registry，片段 ID 带资料与版本，并在每次调用前检查 generation 和停用状态。第一期仍只支持 UTF-8 Markdown/TXT 导入，版本差异、结构化规则编辑与 agent 使用试验留到后续。

## 目标与当前事实

在现有管理台增加「知识库」入口 `/ui/#knowledge`，放在「智能体」旁边。让管理者能回答：收录了什么、哪些内容可检索、agent 实际使用哪个版本、为什么这次没查到，以及怎样更新或停用资料。

2026-11-03 本地代码与资料核查结果：

- 当前只有《把时间当作朋友》第三版，源提交为 `ba8305dc38a1868b78acf44136d1a0d3bf5d0af2`。
- 保存 87 个原文件；当前 worker 检索其中 11 个 Markdown 文件，按标题生成 135 个片段。72 张图片、3 份 PDF 和许可文件不参与全文检索。原文件总数不能显示为「可检索文档数」。
- `tools/knowledge/server.cjs` 的 `BOOK`、工具描述及加载入口目前绑定这一本书；启动时读入内存。只做前端页面，不能获得多资料管理与更新生效能力。
- 实现前管理台尚无知识库 API；现在列表、详情、导入、发布、启停、试搜和原文读取均已接入，worker 状态从 `knowledge/.runtime/worker-status.json` 读取并区分已加载、待生效、失败和未确认。

资料用于按需检索，不将整本书塞进系统提示词。知识库、提示词和家庭成员记忆分开管理；本次范围只涉及参考资料。

## 页面与交互

沿用现有侧栏、字体、浅色/深色主题、表单、toast 和 hash 路由。页面提供三个标签：「资料」「检索试验」「使用规则」。不额外新建一套后台。

### 资料

主列表每行是一份逻辑资料，书籍的多个文件归在一行。展示名称、作者/来源、资料类型、可检索覆盖、启用状态和实际生效版本。无资料时给出添加入口；列表较多时再显示名称筛选。

点击行展开详情：

1. **概览**：说明、主题标签、适合使用的场景、启用开关。
2. **内容**：文件目录、已索引/仅保存/解析失败标记、章节与原文预览。原文只读；自编笔记通过新版本编辑，不能直接改第三方原书。
3. **来源与版本**：数据层保留来源、许可、固定提交和文件校验；书架默认只显示作者、文件数、片段数和生效状态，来源/许可等审计信息不占用主界面。版本记录收在详情底部，支持发布及回滚。

目录和片段按需分页。直接阅读原始文本，不执行 HTML、脚本或外部指令；图片/PDF 未解析时明确写「已保存，未索引」。

启用状态与就绪状态分开：

| 维度 | 状态示例 | 展示语义 |
| --- | --- | --- |
| 管理者设置 | 启用 / 停用 | 是否允许后续新检索使用 |
| 导入任务 | 待处理 / 解析中 / 校验失败 / 完成 | 文件处理结果 |
| 索引与发布 | 未发布 / 可用 / 更新失败 | 哪个完整版本可被激活 |
| 运行时 | 未确认 / 已加载某版本 / 加载失败 | agent worker 实际可读取什么 |

「文件导入完成」不等于「agent 已可用」。发布后必须收到 worker 加载确认；未确认时显示「待生效」。界面保留上次成功时间和本次错误，不用一个绿色状态掩盖部分失败。

### 添加书籍

第一期支持 UTF-8 Markdown/TXT 上传，以及已审核来源的固定版本书籍导入。主表单只要求书名和文件，作者与说明可选；一次可以选择同一本书的多个章节文件。来源、主题标签、许可和使用场景不是个人自用资料的必填项，默认收在数据层而不挤占书架。导入校验成功后默认直接发布。

流程：选择来源 → 预览文件与解析覆盖 → 导入并校验 → 发布供 agent 使用。未完成预览或文件校验时不可发布。对相同内容提示复用已有版本；同名不同内容由用户选择新资料或新版本，不静默覆盖。

内置书籍用已有下载器与清单。泛化的 GitHub 仓库、任意网页抓取、PDF/EPUB/OCR 放在后续阶段；不能把「能保存 PDF」当成「能读 PDF」。暂不做登录态抓取或定时自动追随上游最新版本。

更新在暂存区完成，显示新增/变更/失效文件及覆盖变化，校验成功才切换发布版本。失败保留旧版可用。停用保留原文件与历史版本；删除单独二次确认，不能和停用共用按钮。

### 检索试验

输入问题并选「全部书籍」或单本资料，返回命中片段、书名/文档名、章节和原文。点开可读原文和分页；内部保留版本与位置信息用于一致性，但不把许可证、提交号等审计字段展示在主结果里。没有命中时明确反馈；不伪造匹配概率或相关性百分比。

默认直接调用与 agent 相同的检索与读取实现，不启动对话、不播放声音、不触发音乐或家电工具。页面显示本次索引版本，便于和 agent 工具日志对照。

两级验证要分清：

- 「检索试验」检查是否找到、读到正确原文。
- 后续「agent 使用试验」检查是否会查、如何解释，只开放知识库工具并记录实际工具调用；不冒用主语音 thread。首期不必实现此按钮。

### 使用规则

全局默认：有明确方法求助或要求出处时按需查，普通闲聊/倾诉不强行查；通常读一两个片段；先找再读；失败说明不确定；书中步骤与自己的建议分开；不朗读路径和工具名。

每份资料维护「适用主题」「建议使用情境」「不适用说明」。这些是模型的选材指导，不是可靠的权限隔离。例如一本成人经验书不能仅因标签含「学习」就作为针对儿童的确定结论。

第一期规则只读展示目前生效规则，并给出统一提示词配置入口，避免出现两个互相覆盖的编辑器。以后若支持结构化编辑，需要单一来源生成规则，并同时显示已保存与当前 thread 生效版本。变更 `baseInstructions` 仍须建立新 thread；资料内容更新走索引发布，不应每次重建会话。

「停用」在检索层强制执行，和模型是否遵循使用建议无关。已读入会话的文字无法通过停用追溯移除；需要清除旧上下文时另走现有会话重置操作。

## 接入现有 harness

```text
管理台 #knowledge
        │ 管理 API（现有认证、任务进度）
        ▼
Go chat：资料登记、导入任务、版本发布、审计
        │                 │
        ▼                 ▼
资料清单/不可变版本     受限 stdio 客户端
        ▲                 │
        └── Node 知识库读取与检索模块 ◀── Codex MCP 工具
```

Go 服务负责写入，现有 Node worker 保持只读。抽出同一份加载/切分/检索实现供管理端试搜和 MCP 使用，不在 Go 再实现一套排序。Node/Go 用受限结构化消息传递资料 ID、版本和检索参数，不接受管理 API 传任意 shell 命令。

管理端与 Codex 可能是不同 worker 进程：都必须返回实际 registry generation 与内容版本；相同文件路径不代表已经加载同一快照。管理页分别显示已发布与 agent 实际加载情况。运行时状态可通过 Codex 的知识库状态工具核验，协议接入方式在实现阶段确认；不能拿管理端新起的健康进程冒充 agent 当前进程。

将单本书加载改为资料登记表，兼容迁移现有 `source.json`。检索工具的名字先保留 `search_book` / `read_book_section` 以减小迁移范围，增加可选资料范围，描述改为通用资料检索；以后统一命名时需迁移提示词与评测。片段标识必须包含资料和版本，避免不同文档的 `Chapter3:375` 冲突。旧标识仅兼容当前固定书籍版本，不能指向新版本的同一行号。

### 版本与生效

示意目录（不要求照此重排现有原文，实施时先做兼容迁移）：

```text
knowledge/
  registry.json                    # 登记表与当前 generation
  sources/<source-id>/
    versions/<version-id>/          # 原文、manifest、索引元信息；只读
    staging/<job-id>/               # 尚未发布的导入内容
```

发布按「写暂存 → 校验 → 构建 → 提交版本 → 原子替换登记表」执行；Windows 需使用可恢复的原子替换策略并覆盖占用/失败测试。登记表带 generation/ETag，并发发布需要版本检查，不允许后写静默覆盖先写。

worker 在每次工具调用前检查 generation，完整加载成功后整体切换快照。单资料失败保留上次有效内容并报告错误，不拖垮其他资料；首次失败且没有旧版的资料不可用。停用检查先于旧快照回退，停用资料不能因加载失败重新出现。

搜索返回带资料、版本和片段 ID 的引用；读取应访问同一不可变版本，不能把旧搜索结果解释成新版行号。旧引用超过保留期时提示重新检索；不自动替换。发布与读取并发时覆盖这条约束。

停用确认后，后续新 search/read 均拒绝该资料；正在返回中的调用可能已交付内容，停用不能撤回。主 thread 已获得的上下文同样保留。无须为停用重启音箱或语音进程。

### API 边界（已实现）

| 接口 | 用途 |
| --- | --- |
| `GET /admin/api/knowledge` | 资料列表、覆盖、发布版本和运行时状态 |
| `GET /admin/api/knowledge/{id}` | 来源、文件目录、版本、使用说明 |
| `POST /admin/api/knowledge/imports` | 上传或固定来源导入；返回任务 ID |
| `GET /admin/api/knowledge/jobs/{id}` | 任务阶段、错误及校验摘要 |
| `POST /admin/api/knowledge/{id}/publish` | 带预期 generation 发布指定版本 |
| `PATCH /admin/api/knowledge/{id}` | 名称/主题/启停；带预期 generation |
| `POST /admin/api/knowledge/{id}/rollback` | 发布旧的已核验版本 |
| `POST /admin/api/knowledge/search` | 与运行时一致的检索及版本信息 |
| `POST /admin/api/knowledge/read` | 带版本的片段读取，支持分页 |

沿用管理台认证；列表不回传凭据、完整主机路径或生产配置。网络导入只接固定来源下载器；未来通用 URL 导入要单独限制目标和重定向。上传限制体积、扩展名、编码及路径，拒绝越界/符号链接；UI 按纯文本展示外部内容。导入内容只作为参考，不能变成 agent 系统指令。

## 分期与验收

**第一期：真正可用的管理闭环。** 资料列表、目录与原文、校验状态、试搜、启停、多资料登记、Markdown/TXT 导入与版本发布；内置书籍来源保持固定提交。规则先只读展示。使用现有 Go + Node，不增加向量数据库、Docker、OCR 等运行依赖。

**第二期：更新与回归。** 版本差异、发布回滚界面、检索案例保存、只开放知识库工具的 agent 试验；结构化使用规则及其生效管理。

**第三期：扩展格式。** 根据实际需要再增加受限 GitHub 来源、网页、PDF/EPUB 和 OCR；逐项报告解析覆盖与失败原因。

首期验收必须包含：

- 展示 87 个保存文件、11 个可检索文件、135 个片段，不混淆保存与解析。
- 「记录开销 第三组练习」命中并读到正确两周安排，正文和出处一致。
- 添加第二份资料后可检索，片段 ID 与原书不冲突；在管理端与实际 agent worker 分别确认版本。
- 停用后新检索/读取不能访问，重启后仍停用；界面说明已进入会话的内容仍存在。
- 错误编码、校验失败、发布中断和并发发布都保留旧版，显示可定位的中文错误。
- 发布发生在搜索与读取之间，仍读到搜索时版本或明确要求重搜。
- 本页试搜不触发扬声器、音乐、家电或主 thread；不要求升级音箱 client。
- 浅色/深色主题、窄屏、键盘操作及空/加载/失败状态可用。

## 本次交付边界

配套交互草案使用本地已校验资料的统计与少量真实片段；其启停、添加和检查按钮仅演示交互。没有管理 API、生产 worker 健康探测或真实导入，也未修改现有语音服务、前端路由或生产配置。

草案已在浏览器检查：检索样本切换、原文展开、停用后拒绝返回样本、添加后显示未发布草稿，以及自由问题明确提示尚未连接。360px 布局已目视核查，320px 下内容宽度与容器一致；JavaScript 语法检查通过。正式管理功能的验收仍需实现后进行。
