# B 站合集、分 P 与播放队列

## 管理台

在 `/ui/#bilibili` 输入歌曲关键词搜索；输入 BV 号或 `bilibili.com/video/BV...` 链接则读取目录。链接的 `?p=2` 会保留分 P 选择。搜索结果上的“合集 / 分 P”也能打开目录。

页面分别显示“所属合集”和“当前视频分 P”，可单独播放一项、从指定项连续播放、从头顺序播放或打乱顺序。下一项切换视频 / 分 P，不能保证切换到长视频内的下一首歌曲。

查看目录只请求元信息，不下载音轨。详情接口的 `ugc_season` 包含完整目录时保留作者分区与顺序；不完整时使用 `seasons_archives_list` 分页读取，按 BV 去重并核对总数。分页失败、重复页或数量变化会报错，不把第一页伪装成整个合集。当前接受完整视频链接或 BV 号，不解析 b23 短链接、直接合集主页链接。

## 队列和取消

- B 站与网易云共用媒体操作锁、音乐管理页、设备自然结束回调和暂停 / 继续 / 停止 / 上一项 / 下一项控制。
- B 站单项播放建立单项队列，播完停止；整个合集连续播放，结束后也不退回旧网易云歌单。网易云原有“单次点播后回原歌单”语义保留。
- 用户选定队列后暂停旧媒体，后台准备当前项的音轨；准备过程不占用媒体操作锁，可暂停、停止或切换。只有仍有效的当前任务能下发播放，切歌、停止、选书会撤销旧任务。
- 对话确认语和原生识别未结束时，已准备好的音轨等待本轮语音结束再起播。准备失败保留队列并显示错误，不默默跳过视频。
- 队列和当前项写入配置同目录的 `music-queue.json`。服务重启后不会自行下载或起播，准备中的项目恢复为暂停，用户可以明确继续。当前不保存视频内精确播放书签，重新准备可能从当前项开头播放。
- 复用现有 MP3 播放缓存，只按需准备当前项，不整套下载。缓存键包含 BV 和 CID；永久保存音轨仍需要用户主动点击或要求下载。

## 接口与 agent 工具

| 接口 | 参数及作用 |
|---|---|
| `GET /admin/api/bilibili/catalog` | `reference` 为视频链接或 BV 号，返回视频、选中 CID、分 P 与可用合集完整目录 |
| `POST /admin/api/bilibili/queue` | `reference`、`kind=collection/parts/video`、`index`（从 0 开始）、`shuffle`；成功返回 202，代表受理准备任务 |
| `POST /admin/api/bilibili/play` | `bvid`（也接受视频链接）、可选 `cid`；只播放该项，成功返回 202 |
| `GET/POST /admin/api/music` | 返回当前来源和队列，处理公共播放控制；页面序号从 0 开始 |

MCP 工具：

- `get_bilibili_catalog`：只读目录，`offset` 从 0 开始、`limit` 默认 20，最大 50，避免一次把全部目录塞进对话上下文。
- `play_bilibili_playlist`：`kind=collection/parts`，`start_index` **从 1 开始**。用户明确选择整套 / 全部分 P 时才调用。
- `play_bilibili_music`：单项点播，支持原有 `cid`。
- `next_music`、`stop_music` 操作当前来源；不能把准备成功说成已经出声。
- `control_music` 提供暂停、继续、上一项与重播；本地匹配到“暂停 / 停一下”也走公共队列控制，不再按停止处理。

## 验证与边界

自动化测试覆盖 106 项分四页取全、重复页和中途失败拒绝导入、作者目录顺序、多 P 选择、链接校验、播放完成推进、结束不返回旧网易云、慢请求取消、暂停后继续、队列恢复、切换队列和听书时撤销旧任务。

`BILIBILI_CATALOG_LIVE=1 go test -run '^TestBilibiliCatalogLive$' -v` 只读验证真实目录，不下载或播放。2026-11-04 实测 `BV1qFuQz2EVx` 所属“私人尊享”返回 106 个视频；当前视频只有一个分 P，时长 25475 秒。

当前仍先获取并转换完整音轨再起播，未实现流式转码，也未预取下一项。数小时视频的首次准备可能很慢，并受 `bilibili.max_size_mb` 限制。标题的“100 首”不会自动变成 100 个可切换曲目。本功能不承诺无缝衔接；连续播放与语音插话仍需真机试听验收。
